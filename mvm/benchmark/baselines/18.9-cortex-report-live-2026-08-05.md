# Phase 18.9 live validation — Cortex Report + CLI/MCP

Date: 2026-08-05 (Europe/Moscow)  
Release binary: local Phase 18.9 build  
Camera: `/dev/video0`, 1280×720 MJPG

## Procedure

With the current release binary, a bounded real-camera run was executed:

```bash
target/release/mvm run --max-frames 120 --interval-ms 250 \
  --no-vision-log --scheduling-mode scene-depth
```

The run writes `current_cortex.json` atomically beside `current_state.md`. The
following read-only interfaces were then exercised against that artifact:

```bash
mvm cortex --view attention --top-k 3
mvm cortex --view forecast --horizon-seconds 2
mvm cortex --json
# MCP tools/call: mvm_cortex(view="uncertainty", top_k=3)
```

## Result

The bounded run delivered 120 capture frames with zero agent errors. Health
included `cortex=119` and `cortex-report=125`, proving that the report writer
published independently of the facts StateFile writer. The Scene/Depth permit
path remained live (`scene_extra=12`, `depth_extra=1`), but those outcomes are
operational context, not canonical facts.

CLI attention returned three evidence-linked entity keys and the uncertainty
section retained `withheld`, `unknown`, and explicit reasons such as
`insufficient_evidence`, `occluded`, `low_confidence`, `uncalibrated`, and
`ordinal_only`. Forecast returned its actual bounded 1.000 s horizon rather
than pretending that the requested 2 s was observed or guaranteed. Explicit
`--json` returned the raw artifact only when requested.

The MCP response to `mvm_cortex(view="uncertainty")` returned the same compact
honesty-preserving text. It did not require reading raw JSON, and it did not
alter `current_state.md` or `labels.jsonl`.

## Post-run restoration

Hermes automatically restored its stdio-owned watchdog/producer. A fresh
snapshot then reported 25 FPS and a live `mvm cortex --view self` read an
asserted camera-relative pose while preserving `world pose: unknown` with
`missing_source`; calibration priors stayed explicitly marked.
