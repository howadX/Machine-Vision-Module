# Фаза 15 — ML Refactor: лабораторный пересмотр всей ML-логики → production-качество → v0.2.0

> **Версия:** 0.1 (15 июля 2026)
> **Цель фазы:** полный пересмотр ML-логики MVM на лабораторном фундаменте из двух эталонных
> датасетов — **CMU mocap** (истинная кинематика/время) и **OpenImages** (статика/реляционность,
> breadth) — и доведение её до production-качества по трём осям: **скорость / точность / вес**.
> Релизная цель — **v0.2.0**.
> Dataset Factory перенесена в фазу 16 (`phase-16-plan.md`): фабрике данных нужен измеренный,
> а не предполагаемый, уровень качества ML-слоя.

## Зачем (корень)

Фазы 5–14 построили продукт вокруг ML-компонентов, качество которых **ни разу не было измерено
воспроизводимо**: поза обучена на confounded-наборе (класс≡источник, NB3b), её азимут-тест оказался
циркулярным, z-канал — кросс-доменная бомба (0.93→0.66); стабилизатор и трекер тюнились на глаз;
activity-FSM и anomaly валидировались только живыми прогонами, которые нельзя повторить. Track A
(kaggle-portfolio) дал метод: **эталонные данные + честный протокол + лабораторный журнал**.
Фаза 15 применяет этот метод ко всему ML-слою.

## Эталонная пара (лабораторный фундамент)

| Датасет | Что даёт | Чего НЕ даёт |
|---|---|---|
| **CMU mocap** (~2500 секвенций, 144 субъекта, свободная лицензия) | истинная 3D-кинематика: честный ракурс-бенч, ground-truth переходов/скоростей/flexion, траектории для трекера, golden-сценарии для FSM | объектов, лиц, эмоций, реляционных активностей; lying/falls — инвентаризировать |
| **OpenImages V7** (16M boxes, 3.3M visual relationships, CC BY) | breadth статики: разнообразие людей/ракурсов/сцен; measured-oracle для авто-разметки; реляционная супервизия (holds/rides/on) | keypoints позы, времени/видео, identity/emotion/depth |
| + **gold** (Roboflow, человеческие метки, ~11K) | несущий тест позы (R3-протокол, без циркулярности) | только 3 класса, только статика |

Комплементарность: CMU = truth по времени, OpenImages = breadth по статике, gold = человеческий
якорь. Всё через ЕДИНЫЙ экстрактор (`spike_pose/extract_images.py`, cv2.dnn OpenCV-Zoo) — кросс-сорсовые
выводы не загрязняются кросс-экстракторными.

## Управляющие принципы

1. **Lab-first.** Ни одно изменение ML-логики не попадает в прод без лабораторного подтверждения
   на эталонной паре (+gold для позы). Гипотеза → эксперимент → числа → вердикт → порт.
2. **Каждый этап = лабораторный журнал на Kaggle** (см. «Система журналов»). Этап без журнала
   не считается закрытым, даже если код готов.
3. **Инварианты ядра целы**: минимализм/чистая арифметика (+0 deps на интеллектуальную фичу),
   CPU-first/$0, полный нативный Rust hot-path. Рефакторинг **уменьшает** футпринт, а не растит.
4. **Три оси качества измеряются, не постулируются:** скорость (latency-бюджет по агентам),
   точность (паспорт метрик по компонентам, все числа из живых прогонов), вес (бинарь+модели).
5. **Честность NB3b-уровня:** train/test-домены указаны у каждого числа; CI где уместно;
   отрицательные результаты публикуются в журнале так же, как положительные.
6. **TDD в Rust-части** как всегда: golden-тесты битности Python↔Rust, `cargo test --workspace` зелёный.

## Скоуп: что входит в «ML-логику»

**Наши модели и арифметика (рефакторим):** GRIP-классификатор позы (лес 873КБ) + VAE-OOD (195КБ) +
`compute_features`; PostureStabilizer (dwell-константы); PersonTracker (Kalman, re-link, Hungarian);
activity-FSM + journal; anomaly v2; fusion PoE; ZoneTracker persistence.

**Внешние эксперты (аудируем, НЕ переобучаем):** YuNet, SFace, EmotiEffLib, BlazePose, YOLO26n,
Depth-Anything, handpose — паспорт качества/latency/веса, решения «оставить/заменить/переквантовать».

**Вне скоупа:** capture-слой, MCP/CLI-оболочка (фаза 14 закрыта), Dataset Factory (фаза 16),
Habr-статья (отдельная фаза, здесь — только фундамент журналами).

## Система лабораторных журналов (сквозная механика фазы)

Серия Kaggle-ноутбуков **LJ (Lab Journal), LJ0–LJ6** — по одному на этап. Строятся тем же
kctl-конвейером (`_build_ljX.py` → push → Run-All → fetch), проза и код — **английский**
(стандарт портфолио), внутренние доки — русский.

**Формат журнала — нарратив, не отчёт.** Каждый журнал рассказывает историю этапа по дуге:

1. **Контекст** — что было до нас и почему это не устраивало (со ссылками на прошлые журналы);
2. **Гипотеза** — falsifiable, с заранее названным критерием провала;
3. **Эксперимент** — setup, данные (train/test-домены!), протокол;
4. **Числа** — только из живых прогонов, с CI; таблицы — минимум, выводы — прозой;
5. **Вердикт** — подтверждено/опровергнуто/неоднозначно, включая то, что пошло не так;
6. **Что это меняет** — решение для прода + мост к следующему журналу.

Это одновременно (а) верификация этапа, (б) публичный research-артефакт портфолио и
(в) **сырьё для Habr-статьи**: дуга LJ0→LJ6 = готовый скелет лонгрида «как мы перестроили
ML зрительной системы на честных данных». Пишем каждый журнал так, чтобы главы статьи
собирались из них монтажом, а не переписыванием.

Связь с нарративной аркой портфолио (`kaggle-portfolio/research/NARRATIVE-STRUCTURE.md`): LJ-серия — это
«Статья 2.5» между weak-supervision и архитектурной статьёй; материал LJ1 идёт довеском в NB3b.

## Этапы

### 15.0 — Лаборатория (фундамент, без изменений прода)

- **15.0.1 CMU-конвейер:** инвентарь категорий (сколько реально lying/falls/sit-down — до раздувания
  ожиданий); BVH → маппинг 13 GRIP-суставов → виртуальная камера (175 см eye-level, перспективная
  проекция, азимут-круг 15°) → `mocap_views.npz` (позы + временная ось + истинные метки/углы/скорости).
  Конвертер пишется как переиспользуемый инструмент (секвенции целиком) — он же потом кормит 15.2–15.4.
- **15.0.2 OpenImages-конвейер:** Person-crops → единый MPPose-экстрактор (пилот ~2–3K, Track A/E3);
  реляционные триплеты — инвентаризация под аудит FSM (15.4) и фазу 16.
- **15.0.3 Бенч-протокол:** реестр метрик и фиксированных сплитов (gold-тест заморожен), шаблон
  журнала, kctl-паспорт запуска (commit-hash данных и кода в каждом журнале).
- **15.0.4 Публикация Kaggle-датасетов:** `cmu-mocap-views` (лицензия CMU свободная), pose-наборы.
- **Гейт:** санити GRIP-фич на mocap-проекциях (распределения vs lab/gold); опубликованные датасеты.
- **Журнал LJ0 — «Building the lab»:** почему двум прошлым тестам верить было нельзя
  (confound + циркулярный азимут) и как строится инструмент, которому можно.

### 15.1 — Поза (= Track P, несущий этап)

- 2D-GRIP (z=0) как ведущее представление; `features_13` (vext/hext по 13 несущим суставам —
  воспроизводимость на любом скелете); view-аугментация (mocap-истинная + z-синтез — сравнить);
  structured joint-dropout (desk-паттерн окклюзии).
- Первая честная кривая accuracy(азимут) на mocap-бенче; несущий тест — gold (R3).
- **Flexion-канал вместо 4-го класса:** выход = {standing/sitting/lying} + непрерывный
  `torso_flexion` (REBA-бины у потребителя); ground truth угла — из CMU; `bending_over` собирает fusion.
- **OOD:** class-conditional Mahalanobis на 14 фичах vs VAE (recon/logpz) vs vote-entropy леса
  на реальном OOD-сете (мусорные детекции, животные, деградированные лендмарки).
- **Гейт (переопределён 15.07 по эксп-1):** несущая метрика = **gold R3 cross-domain** (train=lab →
  test=gold5), НЕ in-domain CV (она льстит z-каналу: 3D 0.955 in-domain, но 0.619 кросс-домен). Условие:
  выбранное 2D-GRIP > 3D-GRIP на gold R3 (эксп-1: **0.830 [0.812,0.846] vs 0.619 [0.608,0.630]**, CI не
  пересекаются ✅); азимут-кривая на истинном 3D плоская; Mahalanobis сравнён; итоговый лес сериализован.
- **Журнал LJ1 — «The pose model, rebuilt honestly»** (+ довесок в NB3b: признание циркулярности
  старого азимут-теста — research-integrity ход).

### 15.2 — Кинематика переходов (стабилизатор)

- Из CMU: матрица переходов поз, распределения длительностей (sit↔stand ~1–2 с), вертикальная
  скорость таза **fall vs lie-down** — измеренный порог различения.
- PostureStabilizer: dwell/conf-константы → калиброванный transition-prior (HMM-подобный,
  чистая арифметика, +0 deps); физически невозможные мгновенные переходы подавляются prior'ом,
  а не хардкодом.
- **Гейт:** на mocap-секвенциях prior снижает флип-рейт покадрового классификатора без роста
  задержки реакции > заданной (замерить обе); fall/lie-down разделяются на CMU-падениях.
- **Журнал LJ2 — «Physics of posture transitions»**.

### 15.3 — Трекер на истинных траекториях

- Оффлайн-бенч из CMU-проекций: bbox-траектории с истинной идентичностью; **воспроизведение
  walking-фрагментации** (живая боль: до 7 фантомных треков) как регрессионный тест.
- Kalman process-noise из реальных распределений скоростей/ускорений человека; re-link и
  Hungarian на парных секвенциях (пересечения, окклюзии).
- **Гейт:** фрагментация на walking-бенче ≤ согласованного порога (например, ≤1 лишний трек
  на минуту ходьбы — уточнить по базовому замеру); нулевые регрессии idle-сценариев.
- **Журнал LJ3 — «Why walking people multiply, and how we stopped it»**.

### 15.4 — Симулятор: golden-сценарии temporal-стека

- Инжекция синтетических лендмарок+bbox **после детекторов** → полный прогон
  tracker→Fusion(FSM/зоны/anomaly)→journal/recap; сверка событий с известным сценарием.
- Набор golden-сценариев: вошёл→сел→работает; встал→ушёл; лёг; упал; двое встретились.
- Честная граница: детекторы (пиксельный слой) симулятор НЕ проверяет — только всё над ними.
- Аудит FSM-активностей на OpenImages-реляциях (какие активности вообще подтверждаемы данными).
- **Гейт:** golden-сценарии в CI (`--stub`-класс тестов); anomaly не срабатывает на нормальных
  сценариях и срабатывает на падении.
- **Журнал LJ4 — «A camera that never lies: simulating the world for the fusion layer»**.

### 15.5 — Паспорт внешних экспертов + диета (вес/скорость)

- Per-agent паспорт: latency (замер на эталонном железе), вес, честная точность на доступном
  публичном бенче (emotion/identity/detect) — where feasible, без переобучения.
- Диета по итогам 15.1: VAE (195КБ) убирается, если Mahalanobis выиграл; размер леса
  (873КБ → target по кривой качество/размер); ревизия квантований.
- Latency-бюджет цепочки: подтвердить <50ms CPU человеко-цепочки, зафиксировать по-агентно.
- **Гейт:** суммарный вес моделей и latency НЕ выросли vs v0.1.0 при выросшей измеренной точности.
- **Журнал LJ5 — «Weighing the experts»**.

### 15.6 — Порт в прод + релиз v0.2.0

- Rust-порт победивших решений (TDD): `compute_features` v2 (z=0, features_13), новый лес,
  flexion-выход (⚠️ contract change StateFile/MCP — задокументировать), transition-prior,
  Kalman-параметры, OOD-гейт; golden-тесты битности Python↔Rust.
- Live-валидация на владельческой камере: сидя/стоя/лёжа/наклон × азимуты; walking-сценарий.
- Quality passport в README/AGENT.md (числа из LJ-журналов со ссылками), CHANGELOG,
  релиз v0.2.0 через существующий CI (два job'а, `cargo build -p mvm-cli`).
- **Гейт:** 597+ тестов зелёные, golden-сценарии зелёные, live-чеклист пройден, релиз собран CI.
- **Журнал LJ6 — «Shipping v0.2.0: the scorecard»** — сводный: было/стало по трём осям.

инварианты №1–3. Dataset Factory ждёт в фазе 16 и получает от фазы 15 измеренный ML-слой.
