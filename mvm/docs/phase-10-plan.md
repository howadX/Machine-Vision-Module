# Фаза 10 — Segmentation: точное взаимодействие через инстанс-маски

> **Версия:** 1.0 (30 июня 2026) — выделено из прежней фазы 9 по **модульной границе**:
> Фаза 9 = **Tracker** (доработка `HumanAgent`, +0 ONNX), Фаза 10 = **Segmentation** (новый модуль,
> **+1 ONNX YOLO-seg**). **Предпосылка:** фаза 9 закрыта (робастный body-first трек как спина).
> **Исследовательская база:** `~/wiki/machine-vision/03-segmentation/`, `02-tracking/`.

Канон текущего состояния — `mvm/CLAUDE.md`. Здесь — *как делаем* фазу 10.

---

## 0. Тезис

Цель: **точное взаимодействие человек↔объект** через инстанс-сегментацию. Один forward-pass
**YOLO-seg nano** даёт И object-маски (взаимодействие, instance-разделение), И person-маски
(опц. ассоциация трека при перекрытии тел).

> **+1 ONNX** (YOLO-seg) и **больше ничего**. Mask-декод, контакт, depth-по-маске — **чистая
> арифметика, ноль новых deps**. Cadenced на потоке `SceneAgent` → hot-path-нагрузка ≈ 0.

**Ключ:** маски решают *instance-separation* и *контакт*, но **не кинематику** (движение — фаза 9,
лендмарки/арифметика). **SAM/Mask R-CNN отвергнуты** ($0/CPU инвариант). Caveat: nano-маски грубы на
мелких/дальних объектах потолочного ракурса → выигрыш неоднороден (потому спайк-гейт 10.1 первый).

---

## 1. Карта: каким агентам имеет смысл сегментация

| Агент / сигнал | Сегментация? | Почему |
|---|---|---|
| **G₂ Scene (объекты)** | ✅ **да, ядро** | mask-контакт рука↔предмет, `median_in_mask` для depth (убирает фон-bleed), instance-разделение |
| **G₁ Human — ассоциация трека** | 🟡 **да, опц.** | person-mask → mask-IoU разделяет *перекрытые* bbox (вставляется в cost-матрицу фазы 9) |
| **Posture / Hands / Identity / Emotion** | ❌ нет | лендмарки/кроп лица; силуэт не информативнее |
| **Кинематика движения** | ❌ нет | производные лендмарков (фаза 9) |
| **Depth-модель** | ❌ нет (косвенно) | маска помогает *читать* depth (`median_in_mask`) — объектная сторона |

**Вывод:** сегментация осмысленна для **двух** мест — объекты (ядро) и person-instance-ассоциация (опц.).

---

## 2. Инварианты фазы 10 (жёсткие)

- **+1 ONNX** (YOLO-seg nano) и больше ничего. Mask-декод/контакт/depth-по-маске — чистая арифметика.
- **Cadenced на `SceneAgent`** → hot-path ≈ 0 (mesh уже снял HOL).
- **Person НЕ становится узлом графа.** Person-маска — *только* подсказка ассоциации трекеру (фаза 9);
  узлы людей — из BlazePose (G₁-эксклюзивность).
- **CPU-честность.** На CPU YOLO26n-detect ~39мс; YOLO-seg + декод прототипов → реалистично **~60–90мс**
  на потоке, cadenced. FPS из вики (370 и т.п.) — это GPU.
- **❌ Явно отложено (фаза 11+):** ST-GCN/MPED-RNN/VideoMAE (нейро-действия) — каждое +1 ONNX, вне scope.

### 3.1 Предварительный замер (2026-07-02, yolov8n-seg @ CPU, боевой кадр)

Замер на реальном кадре рига (`/tmp/mvm_scene.jpg`, scene-debug дамп; ⚠️ кадр с
отрисованными оверлеями — recall частично сконфаундирован; чистый дневной кадр обязателен
перед финальным go/no-go — на момент спайка риг в темноте).

| Метрика | Результат | Вердикт |
|---|---|---|
| CPU-латентность (640², warm, вкл. прото-декод) | **~38 мс p50** (первый 124 мс) | ✅ сопоставимо с YOLO26n-detect (~39 мс) — cadenced SceneAgent ок |
| Плотность масок где задетектировано (mask-пиксели / bbox-площадь) | person **0.34**, couch 0.55, keyboard 0.48, cup 0.76 | ✅ фон-bleed реален: `median_in_bbox` читает 24–66% фона → `median_in_mask` — прямой выигрыш |
| Recall мелких настольных объектов | 🔴 **слабый**: из ~5 объектов YOLO26n (2 cup, bottle, mouse) yolov8n-seg нашёл 1 cup даже @conf 0.12; ложный `baseball bat` на ноге | 🔴 drop-in замена YoloDetector → потеря покрытия |
| Person-mask качество | силуэт отличный (0.34 vs bbox) | 🟡 потенциал для 10.7, но нужна мульти-person эмпирика |

**Предварительный вердикт: conditional GO.** Маски дают реальную ценность (depth по маске,
контакт, силуэт человека), но **не как drop-in замена** YOLO26n — recall мелких объектов у
nano-seg хуже детектора. Архитектурный вывод: seg — *дополнительный* cadenced-эксперт (маски поверх
детекций YOLO26n / только для крупных инстансов), либо другая seg-модель. Финальный go/no-go
и решение по 10.7 — после чистого дневного замера (без оверлеев) и, для 10.7, кадров с ≥2 людьми.

### 3.2 Чистый замер (2026-07-02, дневной кадр `/tmp/live0.jpg`, БЕЗ оверлеев)

Повтор на чистом светлом кадре (яркость 113 vs 3.7 ночью) — оверлеи прежнего замера действительно
занижали recall.

| Метрика | Чистый кадр | Δ vs §3.1 |
|---|---|---|
| CPU-латентность (640², warm) | ~47 мс p50 | тот же порядок (~38–47), cadenced ок |
| Recall @conf 0.25 | person, bed, book×2, cell phone×2, dining table, chair (8 инстансов) | больше и стабильнее |
| Recall мелких @conf 0.12 | +cup×3, mouse, laptop — **находятся** (оверлеи их прежде глушили) | 🟢 заметно лучше |
| Mask-плотность (mask/bbox) | 0.51–0.83 (person 0.54, cup 0.70–0.83, table 0.51) | фон-bleed подтверждён |
| Person-mask (силуэт) | чистый контур, исключает кресло/фон (см. `/tmp/live_seg_vis.jpg`) | 🟢 годен для 10.7 |

**Финальный вердикт (1 человек): conditional GO — seg как дополнительный cadenced-эксперт, НЕ drop-in.**
На чистом кадре recall лучше, но YOLO26n всё равно берёт мелкие настольные объекты (cup) на бóльшей
уверенности (0.40–0.55 vs seg 0.13–0.24). Итог: (1) `median_in_mask` depth и mask-контакт — **однозначный
GO** (плотность 0.5–0.8 = 20–50% фона в bbox сейчас); (2) YOLO26n остаётся детектором объектов, YOLO-seg
добавляется **поверх** для масок крупных/средних инстансов, не заменяет; (3) **10.7 person-mask — GO
по качеству силуэта**, но собственно реализация ждёт эмпирики с ≥2 людьми (сейчас риг одноместный).

### 3.3 Реализовано (2026-07-02, коммиты `f9c18a75`, `0275d970`)

**Ядро + детектор готовы и провалидированы против реальной модели:**
- `InstanceMask` (`mvm-scene/mask.rs`): assemble прото×коэфф → sigmoid → crop-to-bbox → 64²-сетка над
  оригинальным кадром; `iou()`, `contains_norm()`, `set_points()`, `frame_coverage()`. Синтетик-тесты.
- `DepthMap::median_at_points` (`mvm-depth`): mask-aware медиана (только set-ячейки, без фон-bleed).
- `YoloSegDetector` (`mvm-scene`, +1 ONNX `yolo_seg.onnx`, gitignored+рецепт): декод `[1,116,8400]`+
  прото `[1,32,160,160]` → `SegDetection{det,mask}`. Model-gated live-тест на `docs/live0.jpg`:
  9 инстансов, person mask-cov 0.092 (плотнее bbox), совпало с Python-спайком.

**Осталось для полной интеграции (следующая сессия — связный кусок + решение владельца):**
1. **Решение стоимости (владелец):** YOLO-seg — второй cadenced-модель ПОВЕРХ YOLO26n (перф: +~47мс на
   cadence-тик, но полный recall) ИЛИ замена (1 модель, но −recall мелких). Рекомендация: **opt-in флаг
   `--masks`**, дефолт off → нулевой перф-хит, владелец A/B-ит вживую.
2. **Слоистость:** `InstanceMask` в `mvm-scene`, но `ObjectState` (что fusion читает для depth) в
   `mvm-core` (не может зависеть от `mvm-scene`). Протащить маску как **плоские данные** в `ObjectState`
   (`mask_points: Vec<[f32;2]>` или low-res `Vec<u8>`+res) — тогда `median_at_points` и point-in-mask
   контакт работают без нарушения слоёв. `TrackedObject.mask: Option<InstanceMask>` + attach по bbox-IoU.
3. **10.4 depth:** в `agents/fusion.rs::anchor_objects` — `median_at_points(mask)` при наличии маски.
4. **10.5 tracker:** mask-IoU тайбрейкер в `ObjectTracker` (переиспользует Hungarian 9.10).
5. **10.6 fusion:** контакт рука↔объект через `contains_norm` (точнее landmark-в-bbox 8.F).
6. **10.7 person-mask:** ждёт кадров с ≥2 людьми (риг одноместный).
