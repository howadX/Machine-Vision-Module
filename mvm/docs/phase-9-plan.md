## 0. Тезис

Цель владельца по Треку B: **(1) трекинг движений Human + (2) робастный, корректный трек как спина
`HumanAgent`.** Архитектура: **Body-first tracking + Face-as-attribute + ByteTrack для робастности.**

> **Тело видно всегда** (даже когда лицо отвёрнуто) → трекаем **тело**, не лицо. Identity/emotion —
> **атрибуты тела**, переживают окклюзию лица. SFace — для долгосрочной ре-идентификации, **не каждый
> кадр**. ByteTrack здесь — **не главный механизм, а страховка** при пересечении людей / редких сбоях
> тело-детектора. Главное — правильный выбор **цели** трекинга (тело) + **инверсия** потока обогащения.

**Footprint:** **+0 ONNX.** Всё (кинематика, ByteTrack, OCM/OCR, Hungarian, гейтинг, lifecycle) —
чистая арифметика и оркестрация над данными, уже лежащими в памяти. Инвариант #1 идеален.

## 1. Что фаза 8 уже даёт (не считаем дважды)

Body-first **во многом уже реализован** — фаза 9 не строит его с нуля:

- ✅ Тело — несущая сущность трека (`NativePose::bodies` → `PersonTracker`).
- ✅ Лицо матчится к телу по носу; identity/emotion/posture/3D — **уже атрибуты `PersonTrack`**,
  переживают пропажу лица (best-conf + decay).
- ✅ Reserved-id «липко на присутствие» — identity уже переживает окклюзию лица.
- ✅ Каскад re-link (cosine SFace / label / center-distance) — **грубый OCR уже работает**.
- ✅ Kalman bbox (State-Gating) + IoU-ассоциация + missed-инерция.

**Дельта фазы 9 — три оси:** (A) **инверсия потока обогащения** в track-gated; (B) **робастность
ассоциации** (ByteTrack-страховка + OCM/OCR); (C) **identity lifecycle с cadenced SFace**.

## 2. Инварианты фазы 9 (жёсткие)

- **+0 ONNX.** Никаких новых моделей. Footprint не растёт.
- **Слоистость (критично).** `PersonTracker` живёт в `mvm-core`, у которого **нет** `ort`/`image`.
  Модели (SFace/emotion/pose) — отдельные крейты. **Трекер НЕ вызывает модели.** Спина оркестрируется
  на слой выше — в `HumanAgent` (`mvm-cli`); трекер лишь **экспонирует запросы** («какие треки без
  identity?», «у каких emotion устарел?», «дай предсказанный ROI»). Любой другой вариант втягивает
  ONNX в `mvm-core` → нарушает слоистость и инвариант #3.
- **Body-primary FRONTIER сохраняется.** Цель трекинга — тело. Лицо — атрибут. Новое/восстановленное
  тело по-прежнему находится detection-first (тело видно всегда).
- **CPU/$0.** Гейтинг SFace/emotion **снижает** нагрузку. Цель `<50ms` CPU держится.
- **ByteTrack по телам, не по лицам.** Low-conf тела идут **только в ассоциацию** (bbox), не в полное
  обогащение — иначе лишние pose/SFace-проходы и мис-роутинг.

## 4. ByteTrack в MVM — специфика (из разбора кода)

- **Цель — тело.** Тело-детектор (`mvm-posture::detector`) выдаёт `Person{bbox,keypoints,score}` со
  `score`, но `BodyPose` его **не несёт**, а детектор **роняет** тела ниже `score_threshold=0.5` *до*
  позы — ровно те low-conf детекции, что нужны BYTE. → 9.4 (a)+(b) обязательны.
- **Дёшево по алгоритму** (~50 строк двухэтапной BYTE), но ценность завязана на сохранении low-conf
  тел. Low-conf тела → **только bbox-ассоциация**, не полное обогащение.
- **Позиция:** страховка робастности при пересечении людей / слабом кадре. Main-выигрыш — от 9.5+9.6
  (инверсия + гейтинг). ByteTrack закрывает хвост робастности.
- **Hungarian (9.10)** окупается там, где есть неоднозначность назначения: **>2 тел** и
  `ObjectTracker` (фаза 10, перекрытые объекты одного класса). Hand-rolled → zero-deps.

## 5. Последовательность и зависимости

```
9.1 (кинематика)  ── независим, идёт параллельно (B1.1/B1.2 готовы)
        │
9.2 (OCM/OCR) → 9.3 (FSM) → 9.4 (ByteTrack) ── робастность ДО инверсии
                                  │             (гейтинг повышает цену swap-а)
                                  ▼
9.5 (инверсия) → 9.6 (id-cadence) / 9.7 (emo-cadence)  ── perf-приз
                                  │
9.8 (лендмарки на треке + эмит)   ── после инверсии (трек владеет данными)
9.9 (ROI-предсказание)            ── после FSM (нужны стабильные треки); трогает FRONTIER → последним
9.10 (Hungarian)                  ── после 9.4 (слой cost→assignment готов)
```

**Робастность (9.2–9.4) делается ДО инверсии (9.5):** track-centric гейтинг повышает цену ошибки
ассоциации (swap мис-роутит identity/emotion) → сначала надёжный матчинг, потом гейтинг.

## 6. Риски и митигации

| Риск | Митигация |
|------|-----------|
| Инверсия (9.5) — высокий blast-radius на самый тестируемый код (`tracker.rs` ~40 тестов) | строгий TDD; поведение на 1 человеке идентично текущему; коммит+live после каждого шага (как 8.0.x) |
| Гейтинг повышает цену swap-а ассоциации | робастность (9.2–9.4) **до** инверсии; ByteTrack-страховка; OCM velocity-consistency |
| 9.9 трогает FRONTIER ROI-источник (ceiling-чувствительность #2) | гибрид detect-first для новых; live-ревалидация 0/1/2/3 чел.; делается последним, изолированно |
| Cadence emotion ломает temporal-PoE | identity кэшируем (sticky, безопасно), emotion — мягкий cadence, согласованный с `forget_lambda` |
| churn-регрессия (как 8.0.3) от FSM/ByteTrack | регресс-тесты churn на быстром движении/окклюзии после 9.2/9.3/9.4 |
| рост памяти от per-track лендмарк-ring | bounded ring фикс. длины; тест отсутствия роста |
