## 0. Тезис и переформулировка

Цель владельца: **(1) точное взаимодействие с объектами И (2) трекинг движений Human.** Это **две оси**.
Прежний roadmap (9.1–9.6) покрывал только первую (объект-маски). Фаза реконструирована в **два трека**,
объединённых **одной новой моделью**:

> **Один forward-pass YOLO-seg даёт И object-маски (Трек A: взаимодействие), И person-маски
> (Трек B: ассоциация трекинга).** +1 ONNX-эксперт на обе цели — инвариант footprint держится.

Критично: **маски НЕ дают «движение».** Корпуса (`03-segmentation`, `04-pose-action`) сошлись —
маски решают *instance-separation* и *контакт*, но не кинематику. «Движение Human» = **траектории
лендмарков во времени = чистая арифметика**. Поэтому Трек B расщепляется на кинематику (без сегментации)
и робастность-ассоциации (с опц. person-маской).

## 1. Карта: каким агентам имеет смысл применять сегментацию

Аналитическое ядро фазы. Каждый агент прогнан через «даёт ли маска выигрыш»:

| Агент / сигнал | Сегментация? | Почему |
|---|---|---|
| **G₂ Scene (объекты)** | ✅ **да, ядро** | mask-контакт рука↔предмет, `median_in_mask` для depth (убирает фон-bleed), instance-разделение объектов |
| **G₁ Human — ассоциация трека** | 🟡 **да, опц.** | person-mask → mask-IoU разделяет *перекрытые телами* bbox, где bbox-IoU сливает/флипает id |
| **G₁ Human — кинематика движения** | ❌ нет | движение = производные лендмарков; силуэт не информативнее 33 точек |
| **Posture / PoseVAE** | ❌ нет | классы поз — из углов суставов (лендмарки) |
| **Hands** | ❌ нет | на nano-разрешении маска кисти грубее 21 лендмарка |
| **Identity / Emotion** | ❌ нет | работают по кропу лица, силуэт нерелевантен |
| **Depth-модель** | ❌ нет (косвенно) | depth уже плотный; маска лишь помогает *читать* его (`median_in_mask`) — объектная сторона |

**Вывод:** сегментация осмысленна ровно для **двух** мест — объекты (взаимодействие) и
person-instance-ассоциация (робастность трекинга при перекрытии). Всё остальное на Human-стороне —
лендмарки/арифметика.

## 2. Инварианты фазы 9 (жёсткие)

- **+1 ONNX** (YOLO-seg nano) и больше ничего. Кинематика, OCM/OCR, mask-декод, контакт — **чистая
  арифметика, ноль новых deps**.
- **Cadenced на потоке `SceneAgent`** → hot-path-нагрузка ≈ 0 (меш уже снял HOL).
- **Body-primary сохраняется**: person-маска — *только* подсказка ассоциации для трекера; person НЕ
  становится узлом графа (узлы людей — из BlazePose, G₁-эксклюзивность).
- **❌ Явно отложено:** ST-GCN / MPED-RNN / VideoMAE (распознавание действий). Каждое — ещё +1 ONNX →
  нарушает scope. Движение в этой фазе — арифметикой; нейро-действия → фаза 11+ как опция.
- **CPU-честность:** FPS в вики (370 и т.п.) — это **GPU (T4/V100)**. На CPU YOLO26n-detect ~39мс;
  YOLO-seg добавляет mask-head + декод прототипов → реалистично **~60–90мс** на потоке, cadenced.
- **SAM/Mask R-CNN отвергнуты** ($0/CPU инвариант): 5–46 FPS GPU, 44–90M params.

## 3. Трек A — object segmentation (точное взаимодействие)

Сохраняет прежние 9.1–9.6, уточнённые.

| # | Задача | Реализация | Гейт/тест |
|---|---|---|---|
| **A0 = 9.1 Спайк-гейт** (первый, обязателен) | Замер выигрыша маски vs bbox/landmark на **боевом ракурсе** | (1) мелкие настольные предметы (под вопросом — nano грубо), (2) близкий контакт рука↔предмет (вероятно да). **Заодно меряем частоту перекрытия person-bbox** (вход для B2b) | задокументированная кривая выигрыша → **go/no-go** |
| **A1 = 9.2 YOLO-seg drop-in** | замена `mvm-scene::YoloDetector`: детект+маски из одной модели | декод prototype-масок (32 прото 160²) × per-instance коэффициенты → линейн. комбинация + sigmoid + crop-to-bbox; чистый `ndarray`/`ort`; +~4МБ ONNX | golden mask vs Python ultralytics; юнит-тесты декода на синтетике |
| **A2 = 9.3 mask-плумбинг** | `TrackedObject`→`ObjectState`→`Entity` несут low-res bitmask + origin | сериализация контракта; бит-маска компактна (напр. 64² u8) |
| **A3 = 9.4 depth по маске** | `median_in_mask` вместо `median_in_bbox` в depth-anchoring | quality-тест: Z объекта точнее vs bbox (меньше фон-bleed) |
| **A4 = 9.5(obj) tracker по маске** | mask-IoU в `ObjectTracker` (разделение инстансов при наложении bbox) | swap-регрессия на перекрытии двух объектов одного класса |
| **A5 = 9.6 fusion по маске** | контакт человек↔объект через mask-смежность/IoU (точнее landmark-точки 8.F) + окклюзия-порядок (кто держит / кто перед кем) | mask-контакт тесты; baseline = landmark-контакт 8.F |

## 4. Трек B — трекинг движений Human

### B1 — кинематика движения (чистая арифметика, БЕЗ сегментации)

Буквальные «движения». Сейчас в системе **ноль** семантических сигналов движения: `Detection`/`PersonTrack`
не несут лендмарков (33 точки BlazePose живут транзиентно в `bodies`/`build_body_primary`), наружу
выведена только внутренняя Kalman-скорость bbox. Greenfield.

| # | Задача | Реализация |
|---|---|---|
| **B1.1 История лендмарков** | кольцевой буфер последних N кадров 33-лендмарков per-track (новое **ограниченное** состояние в `PersonTrack` или `HumanAgent`) | bounded ring, N≈16; память O(N·33), не течёт |
| **B1.2 Скорости** | Δlandmark/Δt (суставы), Δhip-center/Δt (центроид тела); нормировка по `torso_length_m` | чистая арифметика над буфером |
| **B1.3 Переходы состояний** | sit↔stand, idle↔walking по порогам скорости центроида + длительности (dwell) | напр. `centroid_vel<0.05`→idle, `>0.3`→walking; гистерезис против дребезга |
| **B1.4 Жест/reach** | скорость запястья + вынос руки → событие «тянется/машет» (усиливает контакт 8.F) | арифметика; питает `activities` |
| **B1.5 Эмит** | `motion_state` / `velocity` / transition-события на `Entity` → Scene JSON | контракт сериализации |

> Прямой ответ на «трекинг движений»: производные уже считаемых данных, ноль deps, инвариант #1 идеально.

### B2 — робастность ассоциации (OC-SORT-стиль + опц. person-маска)

| # | Задача | Реализация | Гейт |
|---|---|---|---|
| **B2a OCM/OCR апгрейд `PersonTracker`** (чистая арифметика) | **OCM** (observation-centric momentum): добавить в cost матчинга согласованность *направления* скорости трека и наблюдения; **OCR** (recovery): re-link через виртуальную траекторию сквозь окклюзию. Дополняет текущий Kalman+IoU+cosine+center-relink | регрессия churn на быстром движении/окклюзии (как 8.0.3) |
| **B2b person-mask ассоциация** (сегментация, gated спайком) | вернуть класс `person` в YOLO-seg **только для МАСКИ** (не узел!); при перекрытии body-bbox (IoU>τ) разрешать id по mask-IoU; матч маски к BlazePose-телу по носу/лендмаркам | только если A0 показал перекрытие людей как реальный failure-mode на ракурсе |

## 5. Последовательность и зависимости

```
A0 (9.1 спайк) ── обязателен, первый; меряет ОБА трека
   └─ go ─┐
          ├─ Трек A: A1→A2→A3→A4→A5            (объект-маски)
          ├─ B1 (кинематика)                   ∥ независим от масок — можно сразу
          ├─ B2a (OCM/OCR)                     ∥ независим от масок — можно сразу
          └─ B2b (person-mask)  после A1       (нужны person-маски из YOLO-seg)
```

B1 и B2a **не зависят от спайка/масок** — стартуют параллельно сразу. B2b — единственное строго
gated спайком (частота перекрытия людей на боевом ракурсе).

## 6. Риски и митигации

| Риск | Митигация |
|------|-----------|
| nano-маски грубы на мелких/дальних объектах потолочного ракурса → выигрыш неоднороден | A0 спайк-гейт первый; go/no-go по замеру, не презумпции |
| CPU-латентность YOLO-seg (декод прото-масок дороже detect) | cadenced на `SceneAgent`; честный замер ~60–90мс |
| утечка person-узлов в граф (ломает G₁-эксклюзивность) | person-маска ТОЛЬКО в трекер; узлы людей — из BlazePose |
| новое персистентное состояние (буфер лендмарков) | ring-буфер фикс. длины; тест отсутствия роста памяти |
