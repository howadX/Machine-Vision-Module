# Оценка масштабируемости Machine Vision Module

**Дата:** 2026-05-29  
**База:** ~/repos/Machine Vision Module, ветка `legasy_upgrade`  
**Принцип:** не заменять существующий стек, а добавлять новые слои

---

## 1. Где мы сейчас

### Текущий стек (legasy_upgrade)

```
Камера → SCRFD (детекция лица, InsightFace)
           │
           ├── ArcFace 512d (эмбеддинг лица, 99.83% LFW)
           │     └── Cosine similarity → Face ID («Вадим», «Даня»…)
           │
           └── MediaPipe FaceLandmarker (478 3D-landmarks)
                 └── 468 геометрических признаков (расстояния от носа)
                       └── LightGBM → 7 эмоций (48.5% accuracy)
```

### Сильные стороны (НЕ ломать!)

| Компонент | Почему это ЦЕННО | Замена = убыток |
|-----------|-----------------|-----------------|
| **SCRFD** | Сверхбыстрый (2-7ms GPU), нативный ONNX, уже встроен в InsightFace | YOLO для лиц избыточен — SCRFD специализирован и быстрее |
| **ArcFace 512d** | 99.83% LFW, EER 0.4%, угловой margin — лучшая дискриминация | Любая замена потеряет в точности Face ID |
| **MediaPipe 478 landmarks** | 3D-координаты, temporal smoothing, 3-8ms CPU | Другие позёры (RTMPose) дают только 17 точек тела, не 478 лица |
| **LightGBM на геометрии** | Интерпретируемость (видно КАКИЕ точки важны), 100 KB модель, 0.1ms инференс | CNN даст +15-20% точности, но потеряет интерпретируемость |
| **AffectNet 16K** | Реальные лица в дикой природе, 7 эмоций | Свои данные — ключевое преимущество (domain shift к камере) |

### Ограничения (что МОЖНО улучшить)

1. **Только лицо.** Тело, жесты, поза — не анализируются
2. **Только статика.** Эмоция на одном кадре, без временного контекста
3. **Только один человек.** Multi-face есть в теории (SCRFD детектит несколько), но пайплайн заточен под одного
4. **Нет сцены.** Что происходит вокруг человека? Какие объекты?
5. **48.5% потолок LightGBM.** Геометрические признаки не ловят текстуру (морщины, напряжение мышц)
6. **Нет глубины.** Расстояние до камеры только через межзрачковое ~const

## 2. Архитектура масштабирования: слоёный пирог

Вместо замены компонентов — добавляем новые слои ПОВЕРХ существующих.

```
Уровень 0 (ЯДРО — не трогаем):
  SCRFD → ArcFace → Face ID
  MediaPipe 478 → LightGBM → Эмоции лица

Уровень 1 (ТЕЛО — добавляем):
  MediaPipe Pose (33 landmarks тела) параллельно с Face
  + ST-GCN (действия по скелету: «машет», «сидит», «идёт»)

Уровень 2 (СЦЕНА — добавляем):
  YOLOv10m (объекты в комнате) параллельно с Face
  + OC-SORT (трекинг объектов)

Уровень 3 (ГЛУБИНА — добавляем):
  Depth Anything V2 (карта глубины из монокамеры)
  → расстояние до человека в метрах, 3D-позиция объектов

Уровень 4 (ПОНИМАНИЕ — добавляем):
  Florence-2 (описание сцены: «человек сидит на диване с ноутбуком»)
  + ST-GCN + LightGBM → fusion эмоций и действий
```

## 3. Фазы масштабирования

### Фаза 1: Тело (Body Pipeline) — ближайший шаг

**Что добавить:** MediaPipe Pose параллельно с FaceMesh, ST-GCN для действий.

**Почему это естественное расширение:**
- MediaPipe УЖЕ используется для лица (FaceLandmarker)
- MediaPipe Pose — тот же фреймворк, та же экосистема, те же форматы
- Не нужно менять SCRFD/ArcFace/LightGBM — они продолжают работать

**Конкретные шаги:**

```python
# Сейчас:
import mediapipe as mp
face_landmarker = mp.tasks.vision.FaceLandmarker.create_from_options(...)
# 478 точек лица → геометрические признаки → LightGBM → эмоция

# Добавляем:
pose_landmarker = mp.tasks.vision.PoseLandmarker.create_from_options(...)
# 33 точки тела → геометрические признаки тела → ST-GCN → действие
```

**Новый модуль:** `src/pipeline/5_body_action.py`
- Вход: кадр + face_landmarks (уже есть) + pose_landmarks (новые)
- Выход: действие («сидит», «стоит», «машет рукой», «идёт»)
- Модель: ST-GCN на скелете (100+ FPS, 3M параметров, ONNX)

**Что это даёт:**
- Эмоция лица + поза тела = контекст («улыбается + машет рукой» vs «улыбается + скрещены руки»)
- Временной контекст: ST-GCN видит последовательность поз
- Для робота: жест «стоп» = поднятая ладонь
- Для умного дома: «человек упал» = резкое изменение позы

**Потолок точности эмоций с телом:**
- Текущий LightGBM: 48.5% (только геометрия лица)
- + геометрия тела (поза, наклон головы, положение плеч): оценка +5-8%
- + temporal (ST-GCN на последовательности поз): оценка +3-5%
- **Ожидаемый потолок: ~60%** на геометрических признаках лица+тела

### Фаза 2: Сцена (Scene Pipeline)

**Что добавить:** YOLOv10m для объектов в комнате, OC-SORT для трекинга.

**Почему не заменяет SCRFD:**
- SCRFD остаётся детектором ЛИЦА (специализирован, быстрее, точнее для лиц)
- YOLOv10m добавляется как детектор ОБЪЕКТОВ (параллельно)
- Два детектора работают одновременно: SCRFD ищет лица, YOLO ищет объекты

**Новый модуль:** `src/pipeline/6_scene_objects.py`
- Вход: кадр
- Выход: объекты в сцене + их треки
- Модели: YOLOv10m (детекция, 210 FPS) + OC-SORT (трекинг, 28 FPS)

**Что это даёт:**
- «Человек с чашкой» vs «человек с книгой» → контекст эмоции
- «Человек + открытая дверь» → тревога
- Multi-person: SCRFD даёт лица, YOLO даёт тела, OC-SORT связывает их

### Фаза 3: Глубина (Depth Pipeline)

**Что добавить:** Depth Anything V2-S.

**Почему ценно:**
- Межзрачковое расстояние в пикселях → расстояние в метрах (сейчас только ~const)
- 3D-позиция человека в комнате
- Объём объектов (чашка vs кружка)

**Новый модуль:** `src/pipeline/7_depth_context.py`
- Вход: кадр
- Выход: карта глубины, расстояние до человека в метрах
- Модель: Depth Anything V2-S (24M, TensorRT)

### Фаза 4: Понимание (Understanding Pipeline)

**Что добавить:** Florence-2 или Qwen2-VL для описания сцены.

**Почему это венчает пирамиду:**
- Все предыдущие слои дают структурированные данные (лица, тела, объекты, глубина)
- VLM превращает это в текст: «Вадим сидит на диване с ноутбуком, выглядит сосредоточенным»
- Не заменяет LightGBM — VLM получает его выход как контекст

**Новый модуль:** `src/pipeline/8_scene_description.py`
- Вход: кадр + результаты всех предыдущих слоёв
- Выход: текстовое описание сцены на русском
- Модель: Qwen2-VL 7B (multilingual, русский)

## 6. Что НЕ делаем (и почему)

| Не делаем | Почему |
|-----------|--------|
| ❌ Замена SCRFD → YOLOv10m | SCRFD быстрее для лиц (2ms vs 5ms), специализирован, уже встроен |
| ❌ Замена ArcFace → другое | 99.83% LFW не перебить. Оставить как есть |
| ❌ Замена MediaPipe Face → ViTPose | ViTPose даёт 17 точек тела, а не 478 лица. Разные задачи |
| ❌ Замена LightGBM → EfficientNet | Потеря интерпретируемости. Лучше ДОБАВИТЬ EfficientNet как второй классификатор |
| ❌ Внедрение всех фаз сразу | Последовательное: каждая фаза — независимый модуль |

## 7. Риски

| Риск | Митигация |
|------|-----------|
| MediaPipe Pose + MediaPipe Face на одном кадре — двойной инференс | Они разделяют BlazePose/BlazeFace детекторы. Можно переиспользовать детекцию |
| LightGBM на face+body не даст +10% | Реалистичная цель: 48.5% → 55-58%. Остальное — через CNN + temporal |
| YOLOv10m + SCRFD дублируют детекцию людей | SCRFD только лица, YOLO — всё. Не дубликат, а комплемент |
| VLM слишком медленный для real-time | VLM вызывается не каждый кадр, а раз в N секунд (периодическое описание) |
