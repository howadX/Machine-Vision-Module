# Kaggle ML-статьи: нарративная структура портфолио

> Версия 0.1 — набросок, 14 июля 2026
> На основе обсуждения: GRIP → weak supervision → Dataset Factory → будущие модели

---

## Нарративная арка (story arc)

```
Один классификатор → ансамбль → данные → будущее
      GRIP           MVM     Dataset Factory   новые модели
```

**Главная история:** «Как спроектировать систему зрения, которая не просто видит, а порождает данные для моделей, которые ещё не придуманы.»

Это не коллекция разрозненных ноутбуков. Это **траектория инженера**: от конкретного метода (GRIP) к архитектурному мышлению (MVM) к стратегическому (Dataset Factory как источник данных для следующего поколения ML).

Для рекрутёра это читается как: «Человек понимает не только как обучить модель, но и откуда взять данные, как спроектировать систему, и куда это всё идёт.»

## Статьи: 4 основных + 2 appendix'а

### Статья 1 — GRIP: 14 фич бьют VAE ✅ УЖЕ ОПУБЛИКОВАНА

**Тема:** Как спроектировать инвариантность вместо того чтобы учить её из данных.

**Что внутри:**
- 14 viewpoint-инвариантных фич (by design, не learned)
- Grouped 5-fold CV → 0.93 (честно)
- Azimuth-тест: поворот на 90° → падение <0.5 п.п. (сырые координаты: катастрофа)
- 270 КБ модель, <1ms CPU, 0 зависимостей

**Позиционирование:** Не «смотрите какой крутой метод», а «вот что происходит, когда перестаёшь кидать данные в нейросеть и начинаешь думать о геометрии». Тизер к тому, что MVM — это система таких методов.

**Статус:** Опубликована, живые метрики, можно допилить нарратив под новую арку.

---

### Статья 2 — Weak Supervision: ансамбль как разметчик (NB3 + NB1)

**Тема:** Как 11 слабых экспертов размечают данные лучше одного сильного.

**Что внутри:**
- Постановка: у тебя нет размеченного датасета. У тебя есть ансамбль из 11 детекторов/классификаторов, каждый с confidence.
- **Часть A — позы (NB3):** эвристика из 5 правил → 6000 поз COCO с weak-метками → LightGBM (71.7%). Анализ 4 типов шума. Как шум эвристики ограничивает потолок модели.
- **Часть B — эмоции (NB1):** teacher (EfficientNet-B0) → soft-метки → student MLP. Честный анализ: teacher-leakage, почему student не в production.
- **Часть C — фьюжн (новое):** как из 11 сигналов с разной confidence собрать одну согласованную картину. PoE (product of experts) над confidence. Слабые сигналы, сильный aggregate.
- **Кульминация:** «Слабая разметка ансамблем — это не хак, это архитектурный паттерн. И вот как он масштабируется на 11 модальностей.»

**Привязка к Dataset Factory:** «Но ансамбль не просто размечает существующие данные. Он может размечать **новые** данные в реальном времени. А это уже фабрика.»

**Из существующих ноутбуков:** NB3 (Weak-sup) + NB1 (Distillation) объединяются в одну статью с двумя частями. NB3 даёт data-centric историю про позы, NB1 — про эмоции и蒸馏.

**Новое:** Часть C (fusion confidence) — раньше не было в ноутбуках, берётся из mvm-fusion.

### Статья 3 — MVM: архитектура ансамбля из 11 микро-агентов

**Тема:** Почему 11 специализированных моделей на CPU за $0 покрывают 80% сценариев VLM при 0.1% стоимости.

**Что внутри:**
- **Философия:** Structured Decomposed PTT vs end-to-end. «Умей делать одну вещь лучше всех» vs «делай всё посредственно».
- **Архитектура:** Agent Mesh на std::thread, 12 крейтов, 597 тестов, Rust.
- **Детекторы:** полная таблица (11 штук) — что, latency, confidence, ONNX.
- **Body-primary pipeline:** почему тело первично, а лицо — атрибут.
- **Fusion:** 3D scene-graph, PoE, activity FSM, anomaly scorer.
- **Сравнение с VLM:** таблица MVM vs GPT-4V/LLaVA — latency, стоимость, приватность, интерпретируемость.
- **NB2 (PoseVAE) в роли appendix'а к статье:** VAE как OOD-gate — «как отличить known-unknown от unknown-unknown». Не отдельная статья, а секция внутри архитектурной.
- **NB4 (Teardown) в роли appendix'а:** «Почему identity-эмбеддинги не подходят для эмоций — и как мы это исправили». Инженерное суждение, подкреплённое UMAP.

**Для рекрутёра:** «Человек спроектировал и реализовал production CV-систему на Rust с 12 крейтами. Понимает компромиссы ансамбль vs end-to-end.»

**Из существующих ноутбуков:** NB2 и NB4 становятся секциями/appendix'ами Статьи 3, а не отдельными статьями.

### Статья 4 — Dataset Factory: фабрика данных для будущих моделей

**Тема:** CV-пайплайн, который не просто видит, а накапливает данные для обучения моделей, которые ещё не придуманы.

**Что внутри:**
- **Проблема:** датасеты — узкое горло ML. Собрать и разметить 100K примеров дорого.
- **Решение:** MVM уже работает как зрение в реальном времени. Каждый кадр — это готовая разметка от ансамбля. Нужно только начать сохранять.
- **Архитектура:** DatasetWriter как агент Mesh, session grouper, форматы (JSONL + кадры + глубина).
- **Что накапливается:** лица с identity/эмоцией, позы с occlusion-метками, 3D-позиции, активности, anomaly scores, отношения человек↔объект.
- **Экспорт:** PyTorch Dataset, TFRecord, WebDataset.
- **Privacy:** safe/full/anonymous режимы.
- **Что это даёт:** данные для distillation, self-supervised learning, temporal models, anomaly detection — на **своих** данных, не на публичных датасетах.
- **Главный тезис:** «Данные переживают гипотезы. Ты не знаешь, какую модель будешь тренировать через год. Но если данные уже копятся размеченными — когда гипотеза созреет, у тебя будет датасет.»

**Статус:** Фаза 15 — набросок. Статья пишется как research proposal / vision paper. Код — когда фаза будет реализована.

**Для рекрутёра:** «Человек думает на шаг вперёд: не только как решить текущую задачу, но и как система должна порождать данные для следующего поколения моделей.»

**Новый ноутбук:** NB5 — Dataset Factory. Концептуальный + прототип на Python (эмуляция DatasetWriter без полной интеграции в Rust).

## Что с RESEARCH-PLAN?

RESEARCH-PLAN.md остаётся **внутренним планом действий** (ревизия моделей, честные метрики, фазы 0–4). Он не отменяется. Но теперь у него появляется **нарративная рамка**: мы не просто «чиним метрики», мы готовим материал для статей 2 и 3.

Конкретно:
- Фаза 0 (bench harness) → даёт честные цифры для Статьи 2 (сравнение методов)
- Фаза 1 (честное перепроведение) → даёт честные метрики для Статьи 3 (production-статус моделей)
- Фаза 2 (углубление по моделям) → даёт материал для Appendix'ов и новых секций
- Фаза 3 (новые модели) → даёт материал для Статьи 4 (что можно тренировать на данных Dataset Factory)

## Ключевое решение

**Не 6 разрозненных ноутбуков. 4 статьи, рассказывающие одну историю.**

Это превращает портфолио из «смотрите сколько у меня ноутбуков» в «смотрите как я мыслю: от метода к архитектуре к стратегии».
