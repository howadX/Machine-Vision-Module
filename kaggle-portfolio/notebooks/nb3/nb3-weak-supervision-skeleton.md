**Датасет — в production.** Weak-метки из этого ноутбука стали фундаментом для GRIP (NB3b).
Без NB3 не было бы датасета → без датасета не было бы ≈0.93 → без GRIP не было бы `mvm-posture`.

Сам LightGBM-классификатор (71.7%) **заменён** на RandomForest (GRIP) по трём причинам:
- RF проще экспортировать в Rust: бинарный формат ~270 КБ, `include_bytes!`
- LightGBM требует C++-рантайм → лишняя зависимость
- На 14 фичах RF не уступает градиентному бустингу

**Опубликованный датасет** (`coco-poses-weakly-labeled`) — **живой актив**. Производный от COCO, CC BY 4.0.

## 1. `[MD]` TL;DR

> Размечаем 6000 COCO-поз эвристикой (weak supervision) и обучаем LightGBM с Optuna —
> без единой ручной метки. 0 часов разметки → рабочий классификатор.

- **Данные:** COCO val2017 → MediaPipe PoseLandmarker → 33 landmarks
- **Метки:** геометрическая labeling function (5 правил) → ~65-75% precision
- **Модель:** LightGBM + Optuna HPO (balanced_accuracy, 3-fold CV) → 71.7%
- **Ключевой инсайт:** Модель **сглаживает шум эвристики** — обобщает за пределы правил
- **Актив:** опубликованный derived-датасет на Kaggle

## 2. `[MD]` Исторический контекст: проблема отсутствия меток

К 2024 году у нас было:
- Свои позы (capture_poses.py) — сотни кадров, **один человек, несбалансированно**
- COCO val2017 — тысячи изображений с людьми, но **ноль меток standing/sitting/lying**
- Понимание, что модель на своих данных запоминает меня, а не позу

**Выбор:** 50+ часов ручной разметки VS эвристика за 0 часов с известным шумом.
Выбрали эвристику.

## 3. `[MD]` + `[CODE]` Labeling function: как она работает

(Из `extract_coco_poses.py::classify_pose_heuristic()` — 5 правил с confidence)

```
Правило 0 (нет бёдер):     → standing (conf 0.30)
Правило 1 (lying):         голова на уровне плеч + бёдра на уровне плеч → lying (0.80)
Правило 2 (sitting):       колени рядом с бёдрами → sitting (0.70)
Правило 3 (standing):      бёдра значительно ниже плеч → standing (0.75)
Правило 4 (fallback):      → standing (0.45)
```

## 4. `[MD]` + `[CODE]` Честный анализ шума разметки

Это **самая важная секция NB3**. Не «я написал эвристику и она работает». А «я измерил её ошибки».

**Источники шума (4 типа):**

| # | Ошибка | Пример | ~Частота |
|---|--------|--------|----------|
| 1 | Ложный lying | Наклон (тянется, кланяется) → голова на уровне плеч | ~5% |
| 2 | Ложный sitting | Колени чуть согнуты у невысокого → правило 2 срабатывает на стоящем | ~10% |
| 3 | Пропущенный sitting | Колени за кадром / закрыты → правило 2 пропущено → standing | ~15% |
| 4 | Пограничный sitting/lying | Полулёжа в кресле: колени на уровне бёдер, торс горизонтален | ~8% |

**Суммарный шум: ~25-35%.** В ноутбуке — вручную проверить K=100 случайных примеров, вычислить precision/recall эвристики.

## 5. `[MD]` Почему Y-координаты — не те признаки

Эвристика v1 использует **только Y-координаты** (вертикальные позиции). GRIP (NB3b) постфактум показал:
- `torso_inc` (наклон торса к вертикали) — главный для standing vs lying
- `knee_flex` (угол сгиба колена) — главный для sitting

**Эвристика шумная, потому что использует не те признаки.** Углы инвариантны к азимуту. Y-координаты — нет.

В ноутбуке: сравнить confusion matrix эвристики vs confusion matrix GRIP на одном тестовом сете.

## 13. `[MD]` Обобщает ли модель за пределы эвристики?

Ключевой вопрос NB3. Ответ — **частично**:

- LightGBM accuracy 71.7% > precision эвристики (~65-75%) → модель **сглаживает** часть шума
- Но confusion matrix показывает систематические ошибки (пропущенный sitting)
- Потолок качества ограничен эвристикой — нужен другой подход к признакам (GRIP)

## 14. `[MD]` Мост к GRIP (NB3b)

```
Эвристика (Y-координаты, 65-75% precision)
    ↓
LightGBM на инженерных фичах (71.7% — сгладил шум)
    ↓
Анализ ошибок: сидящие без видимых коленей, наклонившиеся стоящие
    ↓
Инсайт: нужны УГЛЫ, а не ПОЗИЦИИ. Нужна ИНВАРИАНТНОСТЬ к азимуту.
    ↓
GRIP: 14 viewpoint-инвариантных фич → RF → ≈0.93
```

Этот слайд — центральный для собеседования. Он показывает data-centric мышление.
