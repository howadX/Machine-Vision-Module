## 1. `[MD]` TL;DR

> Покомпонентный разбор пайплайна распознавания лиц/эмоций с эмпирическим доказательством:
> identity-эмбеддинги (ArcFace, dlib ResNet) **подавляют сигнал эмоции**.
> Нельзя использовать один эмбеддинг для двух задач.

- **Эмпирика:** UMAP эмбеддингов — раскраска по человеку → чёткие кластеры, по эмоции → каша
- **Silhouette score:** by-person ≫ by-emotion (разрыв ~30 п.п.)
- **P0–P3 приоритеты миграции:** обоснованный legacy→modern рефакторинг

## 2. `[MD]` Почему этот ноутбук — для тимлидов

NB4 — самый «взрослый» в коллекции. Он демонстрирует не умение запускать `.fit()`, а **инженерное суждение**:

- Анализ компромиссов (accuracy ↔ latency ↔ размер)
- Приоритизация компонентов (P0 детектор важнее P2 классификатора)
- Честная оценка потолков (SVM ~45% → geometry 48.5% → +body 55-58% → CNN 72-76%)

Тимлид, читающий это, видит: «человек понимает, **почему** он принимал решения, а не просто **какие** модели использовал».

## 3. `[MD]` Исторический контекст: проблема EmoZid'a

NB0 использовал dlib ResNet 128d для эмбеддинга лица, и **те же 128 чисел** подавал на SVM для эмоций. Результат: ~45%.

Почему так плохо? Гипотеза: dlib ResNet (и любой face recognition эмбеддинг) обучен на **triplet loss** — «один человек → один кластер, независимо от выражения лица». Он активно **подавляет** вариативность эмоций как «шум».

Этот ноутбук **доказывает** гипотезу эмпирически.

## 4. `[MD]` Система: legacy vs modern

Диаграмма двух пайплайнов:

```
LEGACY (EmoZid 2019):
  Кадр → dlib HOG → 68 landmarks → dlib ResNet 128d → SVM (poly) → эмоция
  Accuracy: ~45%

MODERN (MVM 2026):
  Кадр → YuNet → SFace 128d → identity (отдельно!)
       → EmotiEffLib B0 ONNX → emotion (отдельно!)
  Accuracy: identity EER 0.4%, emotion ~73%
```

**Ключевое различие:** identity и emotion — **разные модели** с разными эмбеддингами.

## 8. `[MD]` 🎯 Ядро аргумента: identity ≠ emotion

Формальная постановка:

- Face recognition loss (ArcFace, triplet): минимизирует intra-class расстояние, максимизирует inter-class
- «Класс» = личность. Эмоция — «шум» внутри класса.
- → Эмбеддинг **специально обучен игнорировать** эмоциональную вариативность

Следствие: SVM на identity-эмбеддингах (NB0, ~45%) обречён. Нужен отдельный emotion-классификатор (CNN, NB1 → production).

## 10. `[MD]` Приоритеты миграции P0–P3

| Приоритет | Компонент | Legacy → Modern | Выигрыш |
|-----------|-----------|----------------|---------|
| **P0** | Детектор | dlib HOG → YuNet | 100ms → 1.6ms |
| **P1** | Эмбеддинг | dlib 128d → SFace | EER 2.5% → 0.4% |
| **P2** | Эмоции | SVM → EmotiEffLib | 45% → 73% |
| **P3** | Лендмарки | dlib 68 → MediaPipe 468 | NME 5.3 → 2.1 |

Приоритизация обоснована: P0 (детектор) — bottleneck всего пайплайна, без него ничего не работает. P3 (лендмарки) — косметическое улучшение для геометрических признаков.

## 12. `[MD]` Инженерные уроки

1. **Loss-функция determines representation.** Triplet loss → identity, cross-entropy → emotion. Нельзя одной моделью решать обе задачи.
2. **Статистика побеждает per-frame accuracy.** Даже 65% per-frame → 90%+ over time через majority voting.
3. **Бутылочное горлышко — не модель, а детектор.** 100ms HOG → 1.6ms YuNet дало больше, чем любой апгрейд классификатора.
